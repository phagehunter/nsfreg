# NSF Restricted Entities Guide (Independent)

**Live site: <https://curtishoffmann.com/nsfreg/>**

A static, searchable guide to the U.S. restricted party lists covered by NSF's
July 8, 2026 Dear Colleague Letter, **"Prohibition on Collaborations with
Restricted Entities."** Search 5,900+ entries across all 13 lists (BIS Entity
List, DoW Sec. 1260H & 1286, OFAC NS-CMIC, UFLPA, FCC Covered List, and more)
in one place. Built for NSF-affiliated researchers and research administrators.
Project led by [Curtis Hoffmann](https://curtishoffmann.com) —
[share your feedback](https://forms.gle/FavcasB5Feao7jVG6).

> **Independent.** This site is a community resource — not an NSF or U.S.
> government website, not a compliance determination, and not legal advice.
> Every page links to the authoritative sources.

## What's inside

| Page | Purpose |
|---|---|
| `index.html` | Unified search across a snapshot of all 13 restricted party lists (grouped results, agency filters, alias matching) |
| `policy.html` | The DCL explained in plain language: what's prohibited, who's responsible, key dates, open questions |
| `lists.html` | One explainer per list: legal basis, what's on it, update cadence, official link |
| `faq.html` | Plain-language FAQ for researchers and administrators |
| `checklist.html` | Preparation checklists (researcher track + institution track), progress saved in-browser |
| `about.html` | Data provenance, per-list snapshot dates, methodology, limitations |

Every page above is generated by `build.py` from the templates in `src/` and
the data in `data/`, so the header, footer, meta block and JSON-LD exist once
rather than six times, and **every number printed on the site is computed from
the data** rather than typed into the markup.

Supporting directories:

- `src/` — `base.html`, one body template per page, shared partials, and `site.json` (titles, descriptions, nav, JSON-LD type per page)
- `data/` — per-list extracted JSON, `lists.json` metadata (official URLs, authorities, snapshot and publication dates), and `derived/` for values computed at build time
- `pipeline/` — Python scripts that parsed each official source
- `sources/` — where the raw downloads go; not committed, documented in `sources/README.md`
- `assets/` — stylesheet, search engine (`app.js`), checklist script, list metadata (`lists.js`), and the search index (`entities.js`)

No frameworks and no external requests: the site is plain HTML, CSS and
JavaScript, and works offline once loaded.

## Build

```bash
python3 build.py            # regenerate the six pages, both assets, sitemap.xml and llms.txt
python3 build.py --check    # report what would change, writing nothing
```

Standard library only, no dependencies. The build also fails loudly when a
per-list file's declared `count` disagrees with the number of records it holds,
or when `lists.json` is missing metadata for a list.

### Page weight

`assets/entities.js` is the search index and weighs about 1.8 MB. It is loaded
only on the search page, and only once a search actually starts, either when
the search box is focused or when the page is opened with `?q=` or `?list=`.
Everything else a page needs is either in the HTML or in `assets/lists.js`,
which is about 17 KB. The Lists and About pages render their tables and cards at
build time and load no data file at all.

### Derived values

Designation status for the State nonproliferation list is computed, not typed.
Each record's `notes` field carries one measure per authority, separated by
`|`, and each measure carries its own `status:` clause. A record counts as
**Active** when any one measure is still active, and **Lifted or expired** when
every measure has been lifted, expired, terminated or waived. In the current
snapshot that is 147 active and 381 historical. Both are kept in the index,
both carry a badge in search results, and the search page can filter on either.
The per-record working is written to `data/derived/nonproliferation_status.json`
so the classification can be checked by hand.

## Deployment

GitHub Pages serves this repository's `main` branch as plain static files. The
generated pages are committed, so Pages needs no build step of its own; run
`python3 build.py` before committing whenever a template or the data changes.
Any static host works.

## Test locally

```bash
cd <this folder>
python3 -m http.server 8000
# open http://localhost:8000
```

(Opening `index.html` directly from the file system also works — the search
index is a plain `<script>` bundle, so no server is required.)

## Updating the data

The source lists change often (the BIS Entity List changes many times a year).
To refresh:

1. Download the current official publication for the list(s) that changed
   (links in `data/lists.json` or on the About page).
2. Re-run the matching parser in `pipeline/` (each script's docstring names its
   input), or edit the per-list JSON in `data/` directly for small corrections.
3. Update `snapshot`, `source_published` and `source_published_note` for that
   list in `data/lists.json`. `source_published` is the date the publication
   itself carries, in ISO form, or `null` for the five sources that are
   continuously updated web pages with no edition date.
4. Rebuild the site:

   ```bash
   python3 build.py
   ```

5. Commit and push — GitHub Pages redeploys automatically.

`sources/README.md` lists the exact file each parser expects, where it comes
from, and which Python packages the PDF and DOCX parsers need. The raw
downloads are deliberately not committed; the extracted JSON in `data/` is the
citable artifact, and each file records its `source_file` and extraction date.

## Data caveats

- PDF-derived lists (OFAC, DoW, State nonproliferation) can carry extraction
  artifacts, especially in transliterated names.
- The CBP list intentionally includes revoked historical orders — the site
  shows status badges.
- Entities are grouped across lists by exact normalized name only; the same
  organization under different spellings appears as separate results.
- A non-hit is **not** a clearance. Screen the official
  [Consolidated Screening List](https://www.trade.gov/consolidated-screening-list)
  and the per-list official sources for anything consequential.
